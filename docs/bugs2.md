## データ整合性・集計

- [x] 同一リクエスト内の複数D1書き込みが `db.batch()` 未使用で、途中失敗時に不整合が残る（学習計画の複製・要素削除、演習確定、チャットのストリーム後書き込み、科目ツリー更新）
  - `runBatch` 抽象（本番=D1 `db.batch()`、テスト=better-sqlite3向け順次フォールバック）を新設し、学習計画の複製・要素削除＋変遷記録、演習確定の進捗＋チェック履歴を原子化
  - **残課題1**: チャットのストリーム後書き込み（assistantメッセージ保存と進捗加算）はchat/learningのドメイン跨ぎかつ進捗がread-modify-writeのため見送り。`user_topic_progress` に `UNIQUE(user_id, topic_id)` を付与し `ON CONFLICT DO UPDATE` 化すれば原子化可能（スキーマ変更を伴うため別タスク）
  - **残課題2**: 科目ツリー更新の全面batch化はdiffフローの中規模改修が必要なため見送り（配列サイズ上限の導入で被害範囲は有界化済み。同名スキップにより失敗後の再実行で復旧可能）
  - **残課題3**: 演習確定は確定UPDATE成功後に進捗batchが失敗した場合の不整合が残る（コードコメントに明記済み）
- [x] メトリクス日次スナップショット集計の良い質問数カウントに `role='user'` の絞り込みがなく、日次ビュー集計と条件が非対称
- [x] メトリクス日次スナップショット集計の日境界が `<=` 判定のため、翌日0:00:00ちょうどのレコードが当日と翌日で二重計上される
- [x] メトリクス日次スナップショット集計がUTC暦日固定で、タイムゾーンを考慮する日次ビュー集計と同じ日付でも結果がズレる
