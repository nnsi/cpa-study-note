# バグ修正チェックリスト（第2回監査）

調査日: 2026-07-17

第1回監査（`docs/bugs.md`）の修正後に、API認証・セキュリティ / APIビジネスロジック / Webフロントエンド / パッケージ間契約整合性 / 直近追加機能（目次インポート等）の5領域を並列で再監査した結果。前回リストの修正済みバグは再掲しない。チェックは修正実装と回帰確認の両方が完了した時点で付ける。

## AIストリーミング・チャット

- [ ] AIストリーミングの `error` チャンクが無視され、AI呼び出し失敗が成功（`done`）として扱われる（チャット送信・新規セッション送信・学習計画AI提案・論点生成の4箇所。目次インポートのみ正しく処理済み）。特にチャットでは途中まで届いたテキストが完結した回答としてDB保存され、進捗の質問数も加算される
- [ ] 既存セッションへのチャット送信が削除済み（論理削除）論点でも成立し、削除済み論点の進捗が加算される。また階層取得失敗時はユーザーメッセージだけが孤立してDBに残る

## 論理削除の除外漏れ

- [ ] ノート一覧・詳細に削除済み論点・科目配下のノートが混入する（JOIN先の `deletedAt` 未検査）
- [ ] 学習計画の一覧・詳細・要素が削除済み科目名・論点名を表示し続ける
- [ ] 進捗一覧APIが削除済み論点の進捗レコードを返す

## 入力バリデーション

- [ ] 日次メトリクスの日付範囲に上限がなく、`from=0001-01-01&to=9999-12-31` のような指定で日付ループが暴走しWorkerのCPU/メモリ上限に達する
- [ ] 日付スキーマが正規表現のみで `2026-13-01` 等の実在しない日付を受理し、スナップショットが不正な日付キーで別日の集計値を保存し得る
- [ ] 科目ツリー更新のカテゴリ・サブカテゴリ・論点配列にサイズ上限がなく、巨大ペイロードで無制限の逐次書き込みが走る

## データ整合性・集計

- [ ] 同一リクエスト内の複数D1書き込みが `db.batch()` 未使用で、途中失敗時に不整合が残る（学習計画の複製・要素削除、演習確定、チャットのストリーム後書き込み、科目ツリー更新）
- [ ] メトリクス日次スナップショット集計の良い質問数カウントに `role='user'` の絞り込みがなく、日次ビュー集計と条件が非対称
- [ ] メトリクス日次スナップショット集計の日境界が `<=` 判定のため、翌日0:00:00ちょうどのレコードが当日と翌日で二重計上される
- [ ] メトリクス日次スナップショット集計がUTC暦日固定で、タイムゾーンを考慮する日次ビュー集計と同じ日付でも結果がズレる

## 共有スキーマ

- [ ] `topicType` のZodスキーマが `theory/calculation/mixed` のenumだが、編集UIは自由記述日本語（例: 計算・理論・事例）を保存しており実データと矛盾。関連して科目ツリーUseCaseに `difficulty` の型アサーションが残っている

## Webフロントエンド

- [ ] チャットのメッセージ読込中に空状態「この論点について質問してみましょう」が一瞬フラッシュ表示される（履歴のある論点を開いた時、および新規セッションの初回送信完了直後）
- [ ] 目次インポートで画像の縮小処理中に削除ボタンを押すと、縮小後画像のObject URLが解放されずリークする

## テスト・環境
