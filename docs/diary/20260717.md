# 2026-07-17

## 目次インポート機能（toc-import）を Codex 委譲体制で実装

今日から「作業は全て Codex に委譲、メインは判断と検収」という cb-rpg 方式がこのリポジトリにも導入された。その初回として、目次写真 → AI 抽出 → プレビュー編集 → ツリー登録の機能を作った。

### うまくいったこと

- **設計書をリポジトリに固定してから委譲する流れ**は正解だった。Codex は会話コンテキストを持たないので、`docs/feat/toc-import/design.md` に判断済み事項を全部書き、指示文は「設計書に従え + 検収条件」だけにした。バックエンド・フロントエンドとも一発で全テスト green、設計逸脱ゼロで返ってきた。Codex の実装品質は率直に高い。logic.ts の波括弧走査（文字列内エスケープ考慮）などは指示していない品質だった。
- **メインの付加価値は E2E 検収に集約された**。ブラウザで実際に触ったことで、`uploadImage` が Authorization ヘッダーを付けていない既存バグ（ブラウザからの画像アップロードが全部 401）を発見できた。Codex も 1,300 本のテストも捕まえられなかったもので、「curl で動いてもブラウザで動くとは限らない」という test-api スキルの警句がそのまま現実になった。書いたら即検証、は本当に費用対効果が高い。

### 反省

- **自分のシェル操作ミスが2回**。①長い指示文を直接引数に埋めてクオート崩壊（→ ファイル化して `"$(cat …)"` に切替）。②`pnpm dev | head -100` で起動したせいで、head 終了後の SIGPIPE で dev サーバーごと死んだ。バックグラウンド常駐プロセスにパイプを繋ぐな、という基本を踏んだ。ログはファイルにリダイレクトすべきで、次からそうする。
- **レートリミッターの初報が不正確だった**。「topic-generator にもリミッターなし」とユーザーに言ったが、実際は `/api/topic-generator/*` に適用済みで、漏れは toc-import だけだった。index.ts を読む前に diff の断片から推測で発言した。指摘系の発言こそ一次ソースを見てからにする。
- 検証用に mock アダプタへ目次用デフォルト応答を足した。ローカル開発の体験としては正しいと思う一方、「検証のために本体コードを触る」ことには軽い抵抗があった。テスト専用フィクスチャに寄せる設計もあり得たが、既存の defaultMockResponses の思想（収益認識・リースの例が既にある）に合わせる方が一貫すると判断した。

### 委譲体制について正直な感想

「実装は Codex、判断・検収はメイン」は今日の規模（新機能1本 + 小修正）では明確に機能した。ただし検収コストはゼロではない。今日はレビュー・独立テスト再実行・E2E で相応の時間を使った。これを省くと Codex の green 報告を鵜呑みにするだけの構図になり、委譲の規律（反証可能な検収条件 + メインの必須レビュー）が崩れる。速度が欲しくなったときに検収を削る誘惑が出る、というのが将来の一番のリスクだと思う。

### 残課題

- 実写真 + 実プロバイダ（vercel-ai）での最終確認が未実施（OPENROUTER_API_KEY がプレースホルダー）。階層誤認識の実際の頻度はここで初めて分かる。
- 表記ゆれ（trim で拾えない同義語）のデデュープはスコープ外にした。実運用で不満が出たら fuzzy マッチを検討。
